## 15. Discussion
- The dedicated high-quota route removes the prior authentication and low-quota confounders from the strategy matrix.
- The route still uses the repository's existing request path and mock backend target.
- Fault data remains affected by the script's Redis stop/start timing and existing route semantics.

## 16. Threats to Validity
- Local Docker/JVM scheduling affects client-observed latency.
- Fixed-count concurrent load is not a paced arrival-rate model.
- Strategy containers share infrastructure on one host.
- Dedicated route uses a 1-second window and high quota, so it measures limiter overhead more than quota exhaustion behavior.

## 17. Limitations
- No statistical significance testing is performed.
- No source changes were made to add per-strategy tenant isolation.
- Benchmark tenant and route are left in runtime state pending separate cleanup approval.

## 18. Conclusions
- The final strategy matrix is authenticated, parseable, and includes required latency header samples.
- Percentile interpretation must remain population-specific: successful-path, rejection-path, and all-response values are not interchangeable.

## 19. Recommended Future Work
1. Add approved per-strategy tenant or key isolation in benchmark orchestration.
2. Add a repo-supported cleanup command for benchmark tenants/routes.
3. Add paced-load experiments for steadier arrival processes.
